Poppy Inspector

How the Inspector works

The Inspector is a testing tool. It plays the part of an AI agent, introduces itself to a company's website, and shows every message that passes between them. This page follows one session, from signing in to the end of the standard test run.

Who is involved

  • YouSign in, press Run journey and read the results.
  • The InspectorOur tool. It runs a real AI agent and records each exchange.
  • Identity providerCurity. It checks who you are, so the Inspector never handles your password.
  • Company siteThe website under test, a demo travel company. It decides whether to trust the agent.

Passwords stay put

Your password goes only to the identity provider. The Inspector receives a signed statement that you have signed in.

Every request is signed

Each request carries a signature and is tied to a key. A copied token is useless without the key that goes with it.

You see it all

Each exchange appears on screen. Tokens and signatures are masked on the server before anything reaches the browser.

Part 1

Signing in to the Inspector

Only people on a short approved list can use the Inspector, because it sends live requests to a real site. Sign-in uses OpenID Connect with PKCE, the standard way to sign in through an identity provider.

  1. A

    Start the sign-in

    What happens
    You open the Inspector. It sends your browser to the identity provider, along with a challenge it has just made up.
    What is sent
    The Inspector's name, a fingerprint of a random secret it keeps to itself (the PKCE challenge), and a random reference for this attempt.
    Why it is safe
    The fingerprint cannot be turned back into the secret. Only the Inspector can later prove it started this sign-in.
  2. B

    You sign in

    What happens
    You enter your credentials on the identity provider's own page. It sends your browser back to the Inspector with a one-time code.
    What is sent
    Your password goes to the identity provider and nowhere else. The code comes back through your browser.
    Why it is safe
    The code works once and means nothing on its own. Someone who copies it cannot use it without the Inspector's secret.
  3. C

    Swap the code and check it

    What happens
    The Inspector's server hands the code, its own client secret and the original random secret to the identity provider. It gets back a signed statement of who you are.
    What is checked
    The statement is signed by the identity provider, made for the Inspector, still fresh, and from this same sign-in attempt. Your email must be on the approved list.
    What you get
    A session cookie that the browser cannot read from page code. No tokens are kept in the browser.

Part 2

The test run

Run journey performs four steps against the company site. Each step builds on the one before. If a step fails, the run stops and shows the company's own error.

  1. 1

    Discover the company

    What is sent
    A plain request to a public address on the company's site, /.well-known/poppy.json.
    What comes back
    The company's business card: its name, which version of the protocol it speaks, which interfaces it offers and which permissions exist.
    Why it is safe
    It is public information. No credentials are involved.
  2. 2

    Start a session

    What is sent
    Two signed statements, one saying which agent this is and one giving the agent's identity with this company. A single-use stamp ties the request to a fresh key made for this session.
    What comes back
    A session token that lasts an hour and is locked to that key. The company first looks up the Inspector's public ID card and keys, which the Inspector publishes at its own address, to check the signatures.
    Why it is safe
    Each stamp can be used once, for one request. Without the key, a stolen token does nothing.
  3. 3

    List the tools

    What is sent
    A request to the company's tool service, using a second token that works only for that service.
    What comes back
    The tools an agent may use there, each with a short description, such as searching for flights. The tool service follows MCP, the common standard for this.
    Why it is safe
    A token for the tool service is refused everywhere else.
  4. 4

    Use a public tool

    What is sent
    A flight search. Like every request, it carries its own fresh stamp.
    What comes back
    A list of flight offers.
    Why it is safe
    Anyone may use this tool. It touches no personal data and needs no sign-in.

What you see on screen

Each step shows a tick or a cross. Open a step to read every request and response behind it. When the company refuses something, the likely causes are listed next to it. Each signed token is opened up, with its contents checked against the rules the company applies. The signature itself is never shown.

Beyond the standard run

A longer run adds the steps that need a person. You approve a sign-in on the company's own page. The agent then calls a tool that needs that sign-in and proposes a booking. Nothing is confirmed until you decide, and the run ends by signing out. The Inspector can also send deliberately broken requests to confirm that the company refuses them.

Terms used

Agent
Software that acts for a person, here an AI agent talking to a company's website.
Token
A digital pass the company issues after checking an agent. It is time-limited and limited in what it allows.
Signature
A mark that proves who produced a message and that nobody changed it.
Key
A pair of codes. One stays private and signs. The other is public and lets anyone check the signature.
Session
The period during which the company recognises the agent, tied to one key.
PKCE
A sign-in safeguard. It proves the program finishing a sign-in is the one that started it.
Approved list
The people allowed to use the Inspector, checked after the identity provider has confirmed who they are.
MCP
A common standard for an agent to list and use the tools a service offers.
